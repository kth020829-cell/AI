# 시선 모델 선정 — L2CS-Net

리포트의 `gaze` 축을 어떤 모델로 만들지 정한 기록입니다.

**결론: L2CS-Net으로 간다.** 정확도는 OpenFace 3.0이 근소하게 앞서지만
차이가 기능에 영향을 주지 않는 수준이고, 속도 차이는 리포트 대기시간과
GPU 비용에 바로 영향을 주기 때문입니다.

---

## 어떻게 비교했나

```
표본     실제 면접 영상 9개 (3명 × 3문항)
         안경 착용자 2명 포함
비교군   L2CS-Net  vs  OpenFace 3.0
```

측정한 것

```
드롭아웃률   전체 프레임 중 얼굴 · 시선을 못 잡은 프레임 비율. 0에 가까울수록 좋다
지터         프레임 간 yaw 변화량의 표준편차. 낮을수록 안정적이다
             다만 너무 낮으면 회피 자체를 못 잡는 것일 수 있어 아래에서 따로 확인했다
처리속도     처리시간 / 영상길이. 1.0이 실시간이고 낮을수록 빠르다
```

## 결과 (영상 9개 평균)

| | L2CS-Net | OpenFace 3.0 | |
| --- | --- | --- | --- |
| 드롭아웃률 | 0.001 | 0.001 | 사실상 같음 |
| 지터 | 0.026 | 0.017 | OpenFace가 낮음 |
| 처리시간 / 영상길이 | 3.2배 | 8.6배 | **L2CS가 2.7배 빠름** |

안경 착용자만 따로 보면 드롭아웃률이 **양쪽 다 0**이었습니다. 렌즈 반사로
시선을 놓치는 문제는 두 모델 모두 없습니다.

## 핵심 기능은 둘 다 잡는다

지표가 좋아도 정작 회피를 못 잡으면 소용이 없으므로 따로 확인했습니다.

의도적으로 시선을 두 번 떼고 찍은 영상 하나를 골라 프레임별 yaw를
시간순으로 그려 비교했습니다. **34초~48초 구간에서 두 모델 모두 값이
뚜렷하게 아래로 처지는 패턴이 두 번 나타났고, 위치가 정확히 겹쳤습니다.**
촬영할 때 의도한 회피 타이밍과도 일치했습니다.

그래프 모양 자체가 거의 같고 세로축 기준선만 다릅니다. 좌표계 정의 차이로
보이며, 회피 탐지에는 영향이 없습니다.

## 왜 정확도가 아니라 속도를 택했나

```
지터 차이    0.026 vs 0.017 — 0.01 수준
속도 차이    3.2배 vs 8.6배 — 영상 하나마다 몇 배씩 벌어짐
```

지터 0.01은 회피 구간을 판정하는 데 영향을 주지 않습니다. 위에서 두 모델이
같은 구간을 같은 모양으로 잡은 것이 그 근거입니다.

반면 속도는 사용자가 리포트를 기다리는 시간이고, GPU를 켜두는 시간이므로
비용입니다. 영향이 없는 정밀도를 위해 비용과 대기시간을 몇 배로 늘릴 이유가
없다고 판단했습니다.

## 한계

**표본이 3명뿐입니다.** 일반화하기에는 부족합니다.

다만 뒤집힐 만한 결론은 아닙니다. 속도 차이는 모델 구조에서 오는 것이라
표본이 늘어도 방향이 바뀌지 않고, 정확도 차이는 애초에 기능에 영향이 없는
크기이기 때문입니다. 표본이 늘면 다시 확인하되, 지금 이 결정으로 진행합니다.
