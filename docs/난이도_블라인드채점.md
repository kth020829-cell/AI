# 난이도 블라인드 채점

## 왜 하는가

우리는 질문을 L1 · L2 · L3 세 단계로 나눠 만들고, 리포트에도 그 단계를 표시합니다.
그런데 **사람이 봐서 구분이 안 되면 그 표시는 거짓말이 됩니다.**

지금까지는 LLM이 난이도를 지켰다고 믿고 있을 뿐 확인한 적이 없습니다.
늦게 발견할수록 비쌉니다. 난이도를 줄이면 `session_plan.py`의 배분 로직부터
계약서까지 영향이 가기 때문입니다.

```
정답률 70% 이상    3단계 그대로 간다
정답률 70% 미만    3단계를 2단계로 줄인다
```

---

## 어떻게 하는가

1. 아래 **「배포용」**을 그대로 복사해 팀원 세 명에게 보냅니다.
2. 각자 15문항에 L1 · L2 · L3를 매깁니다. 서로 상의하지 않습니다.
3. 답을 모아 아래 **「정답」**과 대조합니다.
4. 세 명의 정답률을 평균 냅니다.

10분이면 끝납니다.

---

## 배포용

여기서부터 정답 표 앞까지를 복사해서 보내세요.

```
면접 질문 난이도 분류 부탁드립니다. 10분이면 됩니다.

아래 15개 질문이 각각 어느 단계인지 매겨 주세요.
서로 상의하지 마시고 혼자 판단해 주세요.

  L1  사실 확인      이력서에 적힌 내용을 확인한다
                    답하려면 기억만 하면 된다

  L2  근거 요구      선택의 이유와 판단 과정을 설명하게 한다
                    답하려면 "왜 그렇게 했는지"를 꺼내야 한다

  L3  전제 흔들기    답변의 가정에 반박하고 방어하게 한다
                    답하려면 반박에 맞서 자기 판단을 지켜야 한다

지원 직무는 AI 엔지니어이고, 지원자 이력서에는 컴퓨터 비전 프로젝트,
학회 논문 리뷰, 학생회 활동이 적혀 있습니다.


 1. Generative Model을 중급으로 매기시면서 DDPM과 DDIM을 모두 구현하신
    이유는 무엇인가요?

 2. mAP50 0.9944라는 수치가 실사 환경에서의 검출력이 아니라 검증 데이터에
    대한 과적합 신호일 수도 있는데, 어떻게 반박하시겠습니까?

 3. 학생회 임원 20명을 이끄셨다고 하셨는데, 그 안에서 본인이 맡으신 역할은
    정확히 무엇이었나요?

 4. 2D 인식 결과를 3D로 Lifting하는 방향을 택하신 이유는 무엇인가요?

 5. 실사 환경에서 검출률이 떨어지는 도메인 갭을 확인하셨는데, 그 원인을
    무엇으로 진단하셨나요?

 6. 주차장 클러스터링 실패는 방법 선택의 문제가 아니라 애초에 접근 자체가
    잘못된 방향이었던 것은 아닌가요?

 7. 2D 인식 결과를 3D로 Lifting하겠다고 하셨는데, 구체적으로 어떤 방식의
    Lifting을 염두에 두고 계신가요?

 8. 차량 위치 좌표 변환 방식을 직접 설계하셨다고 하셨는데, 구체적으로 어떤
    좌표계 간 변환을 구현하신 건가요?

 9. Generative Model 응용 경험이 적다고 스스로 밝히신 상태에서, 3D Lifting
    방향이 지금 현실적인 목표라고 보십니까?

10. 신입생 OT 예산을 집행하실 때, 무엇을 가장 우선하는 기준으로 두고
    판단하셨나요?

11. 코딩에 대한 두려움을 극복하고 멘토 역할을 맡으셨다고 하셨는데,
    구체적으로 어떤 두려움이었나요?

12. MLOps 역량이 Docker 사용 수준에 그친다면, AI 엔지니어로서 서비스 배포와
    운영을 실제로 책임질 수 있다고 보십니까?

13. 기후변화대응사업단과의 협업 구조를 기존과 다르게 새로 설계하신 이유는
    무엇인가요?

14. MLOps 역량을 초급으로 표기하셨는데, Docker는 정확히 어떤 목적으로
    사용해보셨나요?

15. 도메인 갭을 확인하고도 데모를 그대로 배포해두신 것은, 실사용 신뢰성을
    검증하지 않고 내보낸 것 아닌가요?


답은 이렇게 보내주시면 됩니다.
1-L?  2-L?  3-L?  ... 15-L?
```

## 정답 — 배포할 때는 빼세요

```
 1  L2      6  L3     11  L1
 2  L3      7  L1     12  L3
 3  L1      8  L1     13  L2
 4  L2      9  L3     14  L1
 5  L2     10  L2     15  L3
```

각 단계 5문항씩입니다. 찍어서 맞힐 확률은 33%입니다.

---

## 결과 해석

```
90% 이상    세 단계가 뚜렷하게 갈린다. 그대로 간다
70~89%      쓸 만하다. 그대로 가되 자주 틀린 단계가 있는지 본다
70% 미만    사람도 못 가르는 구분이다. 2단계로 줄인다
```

### 자주 틀리는 짝을 보세요

정답률만 보지 말고 **무엇을 무엇으로 착각했는지**를 세어 보세요.

```
L1을 L2로 착각    사실 확인 질문이 너무 캐묻는 형태다.
                 프롬프트의 L1 예시를 더 단순하게 고친다

L2를 L3로 착각    근거를 묻는 질문이 반박처럼 읽힌다.
                 압박형 어조가 L2까지 물들었을 수 있다

L2와 L3를 섞음    이 둘만 못 가르면 L1 + L2 두 단계로 줄이는 게 낫다.
                 L3를 없애면 압박형 페르소나가 약해지므로
                 대신 꼬리질문에서 압박을 주는 방향을 검토한다
```

### 2단계로 줄이게 되면

바뀌는 곳이 셋입니다. 작지 않으니 결과가 나온 뒤에 판단합니다.

```
ai/llm.py         DIFFICULTY_GUIDE에서 L3를 뺀다
ai/session_plan.py  난이도 배분 로직. 수정 금지 파일이라 합의가 필요하다
계약서             difficulty의 허용값이 L1 | L2로 바뀐다.
                  백엔드 파싱 코드에 영향이 간다
```

## 이 세트의 한계 — 결과 볼 때 감안하세요

**L3 다섯 개 중 네 개가 「~아닌가요」, 「~보십니까」로 끝납니다.**

L3는 전제를 흔들어 반박하게 하는 자리라 한국어로 쓰면 자연스럽게 이 어미가
나옵니다. 그래서 채점자가 **내용이 아니라 말끝만 보고 L3를 골라낼 수 있습니다.**

정답률이 높게 나와도 이것 때문일 수 있으니, 결과를 볼 때 이렇게 나눠 보세요.

```
L1과 L2를 잘 가르는가     이게 진짜로 봐야 하는 것입니다
L3를 잘 골라내는가        말끝 때문일 수 있어 신뢰도가 낮습니다
```

**L1과 L2의 구분이 흐리면 그게 진짜 문제입니다.**

여기 쓰인 질문은 실제 서비스의 프롬프트로 만들었지만 API 호출이 아니라
같은 프롬프트를 서브에이전트에 넣어 뽑은 것입니다. 요금은 들지 않았습니다.
